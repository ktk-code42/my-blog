## 발견한 문제 → 수정 내역

### 1. (버그) "블로그로 돌아가기" 링크 경로 오류
- **파일**: `index.html`
- **문제**: `back-link`의 `href`가 `../../public/index.html`로 되어 있었음. 실제 파일 위치는 `/home/claude/my-blog/app/ktk/2048/index.html`이므로 이 상대경로는 `/home/claude/my-blog/app/public/index.html`(존재하지 않는 경로)로 해석되어 클릭 시 404가 발생하는 버그였음.
- **수정**: `../../../public/index.html`로 변경(2048 → ktk → app → my-blog 세 단계 상위 후 `public/index.html`). Playwright로 `a.href` 최종 해석 경로가 `/home/claude/my-blog/public/index.html`이고 해당 파일이 실제로 존재함을 확인함.

### 2. (사양 누락) 병합 타일 펄스 애니메이션 미적용
- **파일**: `game.js`
- **문제**: `style.css`에는 `.tile-merged`에 대한 펄스 애니메이션(scale 1→1.1→1)이 정의되어 있었으나(spec.md 4.5절), `game.js`의 `render()`에서 병합된 타일에 `tile-merged` 클래스를 부여하는 로직이 전혀 없어 해당 애니메이션이 한 번도 실행되지 않는 상태였음(기능적 버그는 아니지만 spec 미준수).
- **수정**: `moveRowLeft()`가 각 칸의 병합 여부(`mergedFlags`)를 함께 반환하도록 하고, `move()`에서 방향별 회전/반전 변환을 동일하게 적용한 `mergedFlagsBoard`를 계산해 `render()`에 전달, 병합된 칸의 타일에 `tile-merged` 클래스를 부여하도록 수정. 새로 스폰된 타일(`tile-new`)과는 배타적으로 처리(스폰 타일이 동시에 병합 표시로 겹치지 않도록 `else if`로 분기).
- **재검증**: `Math.random`을 고정해 2개의 2가 만나 4로 병합되는 시나리오를 재현, 병합된 타일에 `tile-merged` 클래스가 정상 부여됨을 확인. 이후 200회 랜덤 이동 회귀 테스트에서도 콘솔 에러 없이 정상 동작함을 재확인.

## 최종 결론

체크리스트 15개 항목 중 14개는 실브라우저 테스트로 직접 통과를 확인했고, 1개(2048 타일 도달 시 승리 오버레이)는 도달에 필요한 이동 횟수가 매우 많아 코드 리딩으로 로직 정확성만 확인했습니다(로직 자체에는 결함 없음).

발견된 버그 1건(블로그 복귀 링크 경로 오류)과 사양 누락 1건(병합 애니메이션 미적용)을 `/home/claude/my-blog/app/ktk/2048/` 폴더 내 파일(`index.html`, `game.js`)만 수정해 해결했으며, 수정 후 재테스트로 모두 정상 동작함을 확인했습니다. 블로그 본체 파일은 전혀 수정하지 않았습니다.

**배포 가능**: 예. 위 두 건을 수정한 현재 버전은 핵심 게임 로직(이동/합체/연쇄 방지/점수/스폰/게임오버/최고점수 저장), 모바일 대응(스와이프, 작은 뷰포트, 터치 스크롤 방지), 접근성(키보드 스크롤 방지) 모두 정상 동작하며 콘솔 에러가 없습니다.
