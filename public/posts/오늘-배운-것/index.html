    클로드 코드로 이 블로그를 만들면서, 프레임워크 없이도 세 가지 언어가 각자 어떤 역할을 맡는지 다시 정리해볼 수 있었습니다.

    HTML — 구조와 의미

    HTML은 콘텐츠에 구조와 의미를 부여합니다. 이 블로그에서는 <article>, <header>, <nav>, <time> 같은 시맨틱 태그로 "이것은 글이다", "이것은 날짜다"라는 의미를 코드 자체에 담았습니다. 의미가 명확한 마크업은 스크린 리더 같은 보조 기술이나 검색엔진이 페이지를 더 잘 이해하게 해줍니다.

    CSS — 표현과 반응

    CSS는 그 구조를 어떻게 보여줄지 결정합니다. 이번 프로젝트에서 특히 유용했던 건 CSS 커스텀 프로퍼티(변수)였습니다.

    :root {
  --color-bg: #ffffff;
  --color-text: #1a1a1a;
}

:root[data-theme="dark"] {
  --color-bg: #12141a;
  --color-text: #e6e8eb;
}

    색상을 변수로 빼두면 다크 모드 전환이 속성 하나(data-theme)만 바꿔주면 되는 문제로 단순해집니다. 또한 모바일 우선으로 기본 스타일을 좁은 화면 기준으로 작성하고, @media (min-width: ...)로 점점 넓은 화면을 위한 스타일을 얹는 방식이 반응형 레이아웃을 다루기 훨씬 쉽게 만들어준다는 것도 다시 확인했습니다.

    JavaScript — 동작과 상태

    JavaScript는 정적인 페이지에 동작을 더합니다. 이 블로그에서 JS가 맡은 역할은 크게 두 가지였습니다.

    1. 다크 모드 토글: 버튼 클릭을 감지해 data-theme 속성을 바꾸고, 그 값을 localStorage에 저장해 새로고침 후에도 유지되게 합니다.
    2. 클라이언트 검색: 빌드 시 만들어둔 search-index.json을 fetch로 불러와, 입력한 검색어와 제목·태그를 비교해 결과를 즉시 보여줍니다. 서버 없이도 검색 기능이 동작하는 이유입니다.

    정리

    세 언어의 역할을 한 문장씩으로 요약하면 이렇습니다.

    • HTML: 무엇인지 말한다 (구조/의미)
    • CSS: 어떻게 보이는지 말한다 (표현/레이아웃)
    • JavaScript: 무엇을 할 수 있는지 말한다 (동작/상태)

    프레임워크 없이 직접 만들어보니, 각 언어가 원래 맡도록 설계된 역할이 무엇인지 더 선명하게 느껴졌습니다.
